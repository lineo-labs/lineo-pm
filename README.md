# lines-pm

lines-pm is a modern, self-hosted open-source project management tool built around an interactive timeline/Gantt view.

The guiding principle is simple: lines is a visual, time-based planning and decision-making tool designed for those responsible for the plan, not for those executing tickets.

**Key updates (what the app can do now)**

- **Projects**: create, edit and select projects.
- **Tasks**: create, reorder and edit tasks with statuses (`todo | in_progress | done`).
- **Milestones**: create and edit milestones tied to the timeline.
- **Interactive Gantt**: a timeline view derived from tasks, featuring
  - drag & drop scheduling,
  - auto-zoom based on date range,
  - inline task editing.
- **Synchronized task list**: a task list aligned with Gantt rows.
- **Date-range & drag**: quick date edits via picker and drag interactions.
- **Optimistic UI**: instant client-side updates with backend confirmation (rollback on errors only).
- **Seed data**: example data to try the app immediately.
- **Updates**: append-only, timestamped notes generated by users; they are appended to a project's timeline as storytelling entries (immutable in the UI).

**Behavior & UX**

- Keyboard-friendly interactions and inline editing for fast workflows.
- Subtle animations and immediate feedback to maximize perceived performance.
- The Gantt is a derived view of the task list (single source of truth).
 - Append-only storytelling: `Updates` are instantaneous notes that describe what happened at a given moment. They are appended to the timeline (not edited in-place) and serve as a human-readable log of progress and events.

**Technology stack (current)**

- Backend: FastAPI, PostgreSQL (async SQLAlchemy model), Celery ready for asynchronous jobs.
- Frontend: React, TypeScript, Tailwind CSS, Vite.
- Dev / infra: Docker, docker-compose (development compose file included).

**Run locally (quick start)**

1. Start development containers:

```bash
docker compose -f docker-compose.dev.yml up -d --build
```

2. Frontend served by Vite (usually at `http://localhost:5173`).
3. Backend (FastAPI) exposes OpenAPI docs at `/docs` on the API service URL.

Note: Celery is configured for background tasks; the app works without workers running.

**API & integrations**

- The backend provides a REST API via FastAPI; interactive docs are available at `/docs`.
- The architecture is designed to be extensible (automations, external integrations, optional RAG/AI components).
 - `Updates` are stored as append-only timeline entries and exposed via the API for retrieval and appending; they are intended for audit/storytelling rather than editable content.

**Current limitations (non-goals)**

- No user/permission multi-tenant system in the MVP.
- No production-grade notifications or analytics yet.
- AI is not a dependency: it will be added as an optional, pluggable component.

**Short roadmap**

- CSV import/export
- Task hierarchies
- Gantt UX improvements
- Optional AI provider integrations (plugin model)
